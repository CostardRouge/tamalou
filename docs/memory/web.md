# Web app

`apps/web`: React 19 + Vite 8 + Motion (ADR-0003). Read before touching a screen, the connection, the dictionaries or the build.

## Shape (2026-10-16)

- `connection/`: `GameConnection` is all the UI knows (view, events, send, continueRound, subscribe). `LocalConnection` wraps a `@tamalou/room` `Table` with the real clock; `RemoteConnection` (M6) will speak WebSocket behind the same interface.
- `game/interaction.ts` derives every touchable card and every button from `legalActions(view)`: the screen offers exactly what the engine accepts. Two-touch moves (Jack blind swap, an opponent's card in a quick discard, choose-mode initial peek) are a local `Pending` state, dropped whenever the phase, step, current player or discard top changes.
- `cards/`: `CardTheme` (Face, Back) behind a React context; `CardView` flips with Motion and is a real `<button>` with a French label when playable. Never draw a card elsewhere (ADR-0007).
- `i18n/`: `fr.ts` is the source of keys, `en.ts` is typed against it (`?lang=en` until a switch exists, M8); `test/i18n.test.ts` checks keys and placeholders match. Plurals are `_one`/`_other` keys through `plural()` (French counts 0 as singular).
- Separate `apps/web/tsconfig.json` (DOM + JSX); the root `pnpm typecheck` runs both. `pnpm check` now also builds.

## Decisions and traps (2026-10-16)

- **Quick discard is an armed mode**: the bolt, then a touch on the card. A tap on one's own card during the draw step would otherwise be ambiguous (and a mis-tap costs a penalty card).
- 2026-10-22 — **Quick discard by hand first** (the owner's pick on a canvas: «l'action naturelle serait de faire un drag and drop»). Dragging one of my cards onto the open discard always worked (`drag.ts`), but `ActionBar` made a lone icon act the wide main button, so during others' turns a big green "Défausse rapide" read as the only way. Now the quick act is `minor` (never the wide button, never green) with a `hint` line beside it; `quickOpen` in `GameScreen.tsx` (window open, not my turn, my hand free, not a shared screen whose cards are not the holder's to drag) sets `.game.quick-open`: the discard glows, its label becomes a chip "Jette ici" / "Lâche pour défausser" (over it, z-index above the dragged card), my cards bob (CSS `translate`, never `transform`, which Motion owns; off with reduced motion), the prompt says to drag. Pass-and-play keeps its "who claims" flow.
- **The log speaks to the player in the second person**: an event whose actor is me uses the key's `_you` variant (`logDrewDeck_you`: «Tu pioches.»). A shared «Tu» + third-person verb gave «Tu pioche». **How to apply**: a new log line about an actor gets both keys.
- **Dispose a game when it is replaced, never in an effect cleanup**: StrictMode runs effects twice in development and the cleanup stopped the table on screen. `App.replace()` disposes the previous connection.
- During a Jack, once my card is picked, "Passer le pouvoir" stays offered next to "Annuler" (a UI run got stuck there without it).
- Measured with Playwright at 390×844, light and dark, 2026-10-16: full games to game over through the UI, no console error. Bundle 484 kB (152 kB gzip), mostly React, Motion and Zod; trimming is M8's.
- `base: './'` in `vite.config.ts`: one build works at a domain root and under GitHub Pages' `/tamalou/` (ADR-0010).

## The game master's screen (2026-10-16)

`rules/fields.ts` lists every RuleSet leaf as a setting (path, kind, bounds, `when` to hide a sub-setting of a switched-off option); `test/rules.test.ts` fails if a RuleSet leaf has no setting, so a new rule cannot be forgotten on the screen. `setAt()` changes one leaf, then keeps the initial peek consistent (fixed mode: count = number of slots; a smaller hand drops missing slots) and validates with the schema, returning null to keep the previous rules. `rules/summary.ts` writes the active rules as short French lines and flags those that differ from Classique (`modifié`); the same summary is the editor's preview and the in-game "Règles" panel. The home screen keeps a `RulesChoice` (preset + overrides); picking a preset drops the overrides.

**Trap (2026-10-16)**: `vitest.config.ts` included only `*.test.ts`, so the `.tsx` app tests written for M3 never ran until M4 widened it to `*.test.{ts,tsx}`. **How to apply**: after adding a test file of a new kind, check it appears in the run's file list.

## Pass-and-play (2026-10-16)

One device, several humans (docs/SPEC.md §5.2, ADR-0012). `LocalConnection` takes a list of humans: one is solo, several share the device through `@tamalou/room`'s `Handoff`. The screen shows a player's private view only after "C'est moi, …" on the `HandoffCover` (nothing of the game is drawn on it); while no human has anything to do it shows the table as `SPECTATOR` sees it (every hand face down, all players in the top row, no "mine" grid), and the log is the public one. A quick discard on a shared screen goes "⚡ Défausse rapide" → who → that player's card, computed from that player's own view (`viewOf`) but drawn face down; only own cards can be claimed there. The home screen keeps a `mode` (`solo` | `pass`), the players' names, and `MODE_DEFAULTS` (pass-and-play: quick discard off) sit between the preset and the game master's changes (`rulesOf(choice, base)`), so the editor shows it as a setting to switch back on. Switching mode keeps the changes; picking a preset drops them.

**Traps (2026-10-16)**: `reveal()` changes what the screen shows without any table event, so React never re-rendered — `LocalConnection` now tells its own listeners on reveal. In Playwright scripts, `locator.textContent()` on an absent element waits the default 30 s (the spectator view has no `.mine`): count first, and `page.setDefaultTimeout(1500)`.

## Online rooms (2026-10-16)

The home screen offers "En ligne" only when `api/health` at the site root answers with our protocol version (LAN server, online host); GitHub Pages has no API, so the mode stays hidden there. A room's address is `#room=CODE`, kept in the address bar while inside so a reload comes back; tokens live in `localStorage` `tamalou-rooms` (per code, a day). `RoomClient` (`connection/remote.ts`) owns the socket, reconnects with backoff (1 s → 10 s, at once on `online` / `visibilitychange`) and stops on a final `closed` reason; `RemoteConnection` adapts it to `GameConnection` (`presence()` tags disconnected / bot-played seats). `pnpm dev` proxies `/api` (WebSocket included) to a server on :8080.

**Traps (2026-10-16)**: the room client is created in an effect, not a `useState` initializer: StrictMode's double initializer would open two sockets, and a cleanup-on-unmount would dispose the live one. The online banner floats (`position: fixed`): `.game` is a six-row grid, and an extra child pushed the pile labels under the player's grid. A Playwright run of three phones found a real bug — `Table.submit` compared a held-back draw to `legalActions` with `JSON.stringify`, and an action arriving over the network orders its keys differently, so every early draw was refused as `illegal`; actions are now compared on sorted keys (test in `room.test.ts`). A second tap on a draw already held back is refused `alreadyDrawing`; the client shows no notice for it.

**The API is one folder up (2026-10-20)**: `apiUrl()` resolves `../api/…` from the game page, because the game lives in `play/` (ADR-0017) and both servers serve `/api/*` beside the site. It said `./api/` while the game sat at the root, and the move to `play/` in 0.9.0 sent every room request to `play/api/…`, which answered the page's HTML: "En ligne" vanished on the LAN and online, with no error anywhere. The online test now pins the address from `play/` at a domain root and under a path. **How to apply**: anything the game page fetches from the server is addressed from the site root, never from the page's own folder; a page that moves takes its relative addresses with it.

## Polish (M8, 2026-10-16)

ADR-0015. `feedback/cues.ts` (pure, tested) maps events to one cue per batch and lists the slots a move touched; `feedback/useFeedback.ts` plays it and drives the flash and the splash; `feedback/settings.ts` holds sound/haptics (`tamalou-settings`); the language is `tamalou-lang`, changed through `setLang`, which tells `App` to draw again (no remount: games and rooms keep going). Preset names and descriptions come from the dictionaries (`presetText`), the shared package keeps the French ones as fallback. The installed, offline game is the next section. Verified in Chromium: English switch, splash, both themes.

**Traps (2026-10-16)**: an effect that runs after every render must keep its timers in a ref — its own cleanup would cancel them at the next render (the flash never went away). Audio only starts after a user gesture: the context is resumed on the first `pointerdown`/`keydown`.

## The installed game (PWA, 2026-10-19)

ADR-0020, Versus's model (`docs/pwa.md` there explains each choice; read it before changing the worker). `src/sw/sw.ts` is the worker (own `tsconfig.json`, WebWorker lib, excluded from `apps/web/tsconfig.json`; `pnpm typecheck` runs it), bundled by `build/pwa.ts` as `sw.js`; `closeBundle` reads `dist/` back and writes the precache list and the version in place of `__PRECACHE__` / `__VERSION__`. `manifest()` and `headersFile()` live in `build/pwa.ts`, their facts (`APP`, `THEME`, `SHORTCUTS`, `SCREENSHOTS`, `SCREEN_SIZES`) in `build/site.ts`; `public/manifest.webmanifest` no longer exists. `src/pwa.ts` is a small store read with `usePwa()`: `canInstall` (Chromium's prompt kept for the Settings button), `updateReady` (a worker *installed* while a controller exists: the first install has none, so it never announces itself), `installed`, `iosHint`; `applyUpdate()` posts `skip-waiting` and reloads on `controllerchange`, `dismissUpdate()` forgets the worker. `readShortcut()` reads `?shortcut=` once and drops it; `App` deals at once for `solo` (`choiceFor('solo')`) and hands `mode="pass"` to the home screen. `SHORTCUT_KEYS` in `src/pwa.ts` and `SHORTCUTS` in `build/site.ts` must agree (`test/pwa.test.ts`). `test/pwa.test.ts` also runs the worker against fake caches (install copy-over, the waiting, the fetch routing): extend it with any new route.

**How to check by hand** (done 2026-10-19 with Playwright, served under `/tamalou/` by `http-server`): the first visit of `play/` installs one `tamalou-<v>` cache with the pages under their folders; offline, `play/`, a solo game, `/`, `/en/legal/`, `jouer/#room=…` (forwards) and `play/?shortcut=solo` all work and the fonts come from the cache; a second `pnpm build` (change `VITE_SITE_URL` to change the hash) then `registration.update()` shows the bar; *Plus tard* hides it and the old worker keeps control, a reload brings it back, *Recharger* leaves the new cache alone. The only failing request on a static host is the rooms probe (`play/api/health`), by design.

**Traps (2026-10-19)**: store pages under their folder address only (`./play/`), never `play/index.html`: Cloudflare redirects the file to the folder, and Chrome refuses a redirected response for a navigation (offline would have failed on tamalou.steevepommier.com, GitHub Pages hid it). `FakeCache.match` in the test must honour `ignoreSearch`, as the worker asks it for a `?v=` on a stored file. The screenshots script waits for the "À toi !" greeting to leave before shooting, else it hides the deck. `npm i --no-save` cannot run inside the pnpm workspace from the container: a symlink of a globally installed `playwright-core` (`/opt/node-tools/node_modules`) into `node_modules/` did the job, removed before the commit.

## The table's height and the pinned screen (2026-10-17)

**Bug reported from an iPhone**: the deck and discard overlapped the opponents' seats (Safari's toolbars leave about 390×660). Card widths derive from `--unit`, computed from `100dvh` as well as `vw` (constants in `app.css`); more than three opponents set `--opp-rows: 2` and the class `game-crowded`.

**The owner's rule: the page never moves during a game** («ça sera chiant si on veut bouger une carte et que c'est la page qui bouge»). So `.game` is `position: fixed; inset: 0`, `overflow: hidden`, `touch-action: none`, no text selection or long-press callout, and `html:has(.game)` blocks document scroll and pull-to-refresh. Nothing may rely on page scroll on the table: what must scroll does it in its own box with `touch-action: pan-y` (`.journal`, `.panel`, and `.opponents`). Do not reintroduce `min-height: 100dvh` + page scroll (the first fix did, it was reverted the same day).

**Fitting without scroll**: the grid rows are `auto auto minmax(0, max-content) 1fr auto auto` so the opponents' band is the one that gives way (it scrolls inside itself) while the centre, your cards and the buttons stay whole; `.center` must keep `min-height: auto` (with `0` it collapsed to nothing). Five opponents under 640px tall line their cards up 1×4 (`--opp-cols`), halving their seats. Since the one-line action bar, only 320px-wide phones with five opponents (three rows of seats) get their band clipped into its own scroll.

**How to check a layout change**: Playwright over 390×664, 375×560, 360×640, 430×740, 320×568, 360×520, 390×844 and a tablet, with 2 and 5 bots, comparing the boxes of `.opponents`, `.center`, `.mine`, `.controls` cards, `.game`'s overflow and the controls' bottom against `innerHeight`. To test touch, send raw `Input.dispatchTouchEvent` sequences over CDP: `Input.synthesizeScrollGesture` did not scroll even a scrollable panel, so it proves nothing.

## Rules as cards (2026-10-17)

The owner picked design B for the in-game rules: `rules/RulesCards.tsx`, one card per rule (hand, turn, values, one per power group, quick discard, Tamalou, end, pace), each built from the table's RuleSet through `summarize()` (so a changed value shows as it is tonight and carries "modifié") with a small animated picture drawn by the card theme. ## Flights and the others' bubbles (2026-10-17)

The owner chose "trajectoires physiques" for card movement (row 1, design C) with the soft physics of design D, and for "voir jouer les autres" the recommended design A (bubbles and trajectories) — design B, a hand that hesitates, was suggested for online humans but not built: it would need their pointer streamed, and the owner did not answer for that page. `game/flights.ts` (pure, tested) turns events into flights (`deck`/`discard`/`drawn`/`slot:<player>:<slot>`, a beat each so a batch plays in order) and bubbles (one line per other player, the last move). `game/FlightLayer.tsx` measures every `[data-place]` after each render in a layout effect, keeps the previous measures (a drawn card is already gone when its swap arrives; the middle of the table stands in when it came and went in one batch), flies a CardView copy on a spring (260/18, a thrown quick discard 520/26) and hides the destination (`card-ghost`) until it lands, with a 2.2 s safety. Reduced motion: no flights, bubbles still.

## By hand (2026-10-17)

Design D (soft physics) and the quick discard by dragging (row 3, design C). `game/drag.ts` (pure, tested): `dropsFor(source)` lists where a picked-up card may land, from `legalActions` like every touch — deck or discard onto one of my cards (draw/take, then a queued `followUp` swap once the draw is through, which also waits out a held-back draw) or into my grid's box (`zone:mine`), the drawn card onto my cards or the discard, one of my cards onto the open discard (quick discard) or, during a Jack, onto an opponent's card. `resolveDrop()` takes the card under the finger, asks (`ask` sheet) when the finger sits within 22px of two, and counts a flick at more than 900px/s towards the discard as a drop on it. `Draggable.tsx` wraps a CardView in a Motion drag with a velocity lean on a spring; an accepted drop calls `noteDrop()` so the flight starts where the card was let go, anything else springs back (260/17). Taps, buttons and the armed quick-discard button stay: dragging is a second way to the same moves. Drop targets are excluded from the spotlight's fade (`.card-drop`, `.card-hot`), and bubbles of neighbouring seats step down so they never overlap.

## Hand layouts (2026-10-22)

The owner picked from the 2026-10-22 canvas (https://claude.ai/artifact/Q4neGvh1DhH3UAcwc7fQ3Q, private to him): **keep all six layouts** (grid, row, laid down, arc, fan, carousel), **the row by default**, and **opponents' arcs and fans turned round**, as seen from across the table (pivot by their name, their slot 1 on my right). It is a device setting (`tamalou-settings`: `hand`, `oppHand` "the opponents too"), never a RuleSet field: it changes no rule, and the game master's `hand.columns` now only shapes the grid. `game/hand.ts` (pure, tested) holds the list, `opponentLayout()` (flat and carousel become a row in a small seat; `oppHand` off gives the grid) and the arc and fan geometry (`curve()`: every card in one grid cell turned about a pivot below the hand, span and sag in card widths); app.css sizes each layout from `--base`, `--room`, `--gap`, `--min` per place (`.mine`, `.opponents`, `.hand-mini`), and a line overlaps its cards rather than shrink them below `--min`. A line, arc or fan takes one row, so my cards may grow to 1.8 `--unit` (sized for the grid's two rows). `HandPicker` draws each tile with the layout's own styles and card-theme backs; it sits in the home Settings and in the table's "Affichage" panel, which opens at the top (`.overlay.overlay-top`) so the hand stays in sight. The laid-down hand stands up while a card is carried (`.game.dragging`), so drops aim at cards facing the player. Where cards overlap, a drop takes the card whose middle is nearest (`resolveDrop`).

**Traps (2026-10-22)**: `.hand-row` already existed (the end-of-round panel's revealed hands, `flex-wrap: wrap`), so the layouts are `lay-*` classes; check a new class name with grep before using it. `.overlay` comes later in app.css than the hands' block: a modifier needs `.overlay.overlay-top` to win. The "Affichage" button widened the game bar past 360px wide phones: the bar's tight padding now applies under 400px. The rules follow the layout too (`summary.ts`, the rules cards' hand picture): slots run row by row, so the grid's bottom row is the right-hand end of a line, and outside the grid the summary says "les N cartes de droite" and drops "N par rangée"; `RulesSummary` and `RulesCards` subscribe to the settings so they redraw on a change. The game master's "Cartes par rangée" field only shapes the grid; the home page's tutorial keeps its own 2×2 grid and its "cartes du bas".
