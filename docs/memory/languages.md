# Languages

Read before touching a dictionary, `packages/shared/src/languages.ts`, the language menu or detection, `lock.json` and the `i18n:*` commands, a page's `hreflang`, or the CJK type. The decisions are ADR-0028; the plan and its steps (L0–L4) are `docs/plans/languages.md`, read in full before a step.

## The shape after L0 (2026-11-27)

- **One list**, `packages/shared/src/languages.ts`: code, name in itself, folder, exact `html` lang (`pt-BR`, `zh-Hans`), hreflang, og:locale, `Intl` locale, script, the «Also in English» `offer` line written in the language, `ready`. `ReadyLang` is a type derived from `ready: true`, so `LANDING`, `LEGAL`, `OG_IMAGES`, `CARD_COPY` (all `Record<ReadyLang, …>`) fail the typecheck when a language is made ready without them. Browser code imports it as `@tamalou/shared/languages` (a subpath export): the package's root pulls zod and every schema into the home page's bundle.
- **Three catalogs**, French the source and each language a file typed against it with `export default`: the game's `src/i18n/<code>.ts`, the home page's `src/landing/text/<code>.ts`, the legal notice's `src/legal/text/<code>.ts`. French and English are bundled; the game's others are `import.meta.glob` in `i18n/index.ts` whose pattern **lists the codes** (`./{es,it,…}.ts`), loaded by `setLang` (async; resolves at once for a bundled one, ignores a language without a file, a slow file loses to a later choice) and awaited by `main.tsx` through `ready` before the first render. The home page's script loads its own language's texts only (a glob over `landing/text/`, `index.ts` excluded: it imports all of them for the build). The service worker precaches every `assets/*.js`, so the lazy files work offline with no change there.
- **Which language**: `?lang=` (any code with a dictionary, even not ready: for L1 work) → `tamalou-lang` if ready → the first ready one of `navigator.languages` (`detectLang`: zh-TW/HK/MO and `Hant` → zh-Hant, other zh → zh-Hans, pt-* → pt) → French. Detection is never stored: only a hand choice is (settings, the site's menu, Play on a home page). The home pages never redirect; `landing/menu.ts` adds the `.lang-offer` band under the header when the visitor's preferred language (stored, else detected) is another ready one.
- **Forms**: `plural()` by `Intl.PluralRules(locale)` (`one` → `_one`, anything else → `_other`; French's `many` for a million reads `_other`); `ordinal()` by keys `ordinal_one/two/few/other`, the category from `Intl.PluralRules(…, { type: 'ordinal' })`, a missing one falling to `_other`; dates and lists by `currentLocale()`, never `currentLang()`. The site's links from the game come from `sitePaths()` (`legalDir()` in the list), not from dictionary keys any more.
- **Selector**: the settings list every ready language as `.segmented.lang-list`, each label with its `lang`; the static pages' header has `languageMenu()` — a `<details>` pill (globe + this page's language) opening the versions, each named in itself, the current one `aria-current`; it works without a script, the script closes it outside and on Escape. «Signaler une traduction» (`reportHref`, a `mailto:` to `src/contact.ts`'s address with the language and the build) shows outside French only.
- **Pages**: `PAGES` is generated from `READY_LANGS` (home `<dir>`, legal `legalDir()`), `twin` is gone: `versionsOf(page)` gives every version, the head writes each `hreflang` plus `x-default` → French and `og:locale:alternate`, the sitemap repeats them as `xhtml:link`, llms.txt lists each language. The build sets `<html lang>` from the list, but **each page still needs its shell file**: a language made ready needs `<dir>index.html` and `<dir>legal/index.html`, copies of English's. The 404 page writes French and English and its one inline script (hashed like the others) adds the visitor's language from a JSON of the other ready languages' `notFound*` texts — `{}` while only fr and en are ready.
- **Usage statistics** accept every code (`z.enum(LANG_CODES)`); `/admin/` names them in French (`LANG_NAMES`, a `Record<Lang, …>`).
- **Type**: `src/styles/lang.css`, loaded by every page and written into the 404: system CJK stacks by `:lang(ja|zh-Hans|zh-Hant)` behind the site's fonts (the test holds the stacks to the list's `script`), `letter-spacing: 0` and no capitals forced with `!important` (lint-ignored on purpose), `line-break: strict`, `word-break: auto-phrase` for Japanese, no italic; German buttons and titles hyphenate; `body { overflow-wrap: break-word }` everywhere. The 12 px minimum for CJK text is not enforced yet: L3's captures.

## Keeping translations in step (2026-11-27)

- `apps/web/build/i18n.ts` flattens each catalog (`modes.0.t`), fingerprints the French (12 hex of SHA-256) and compares with `src/i18n/lock.json` (`{ lang: { game|landing|legal: { key: hash } } }`). `test/i18n.test.ts` fails on a missing, stale or unstamped key and on one identical to French outside `SAME_EVERYWHERE` (names, ranks, placeholder layouts, icon ids, «Tamalou» as `barCall`) and `SAME_IN[lang]` (checked by hand: English's «Total», «Menu», «Bot»…). **How to apply**: change French → translate every language → `pnpm i18n:stamp <code>` (stamps every key the file holds; `pnpm i18n:stamp en key…` for some) → `pnpm i18n:status` clean. Never stamp to silence a key that was not translated.
- **The pseudo-language** `?lang=xx-long` (`i18n/pseudo.ts`, a 0.6 kB lazy chunk, works in a build too): French accented letter by letter, each word 40 % longer, bracketed; `short_*` and `botNames` kept. Never offered, never stored, `<html lang="fr">`.
- `pnpm i18n:shots <code>` (`scripts/shots.ts`) drives Chromium on Vite's dev server (Playwright found by CJS `require`, so the cloud container's global copy works), seeded deal, nine screens (home, settings, setup, peek, table, journal, menu, rules, round end) × phone/computer × light/dark into `apps/web/shots/<code>/` (gitignored), navigating by the language's own dictionary. It reports a page wider than the window, a text wider than its button/link/label/cell (overflowing or cut by an ellipsis), and in the pseudo-language a visible text or `aria-label`/`placeholder`/`title` with Latin letters outside a `[lang]` element (bot names and `Intl`'s «et» allowed); exit 1 when it finds one. Not a test: it needs a browser. The rooms lobby is not shot (no server).

## Traps (2026-11-27)

- jsdom and Node both report `navigator.languages = ['en-US']`: with detection, every screen test opened in English. `apps/web/test/setup.ts` (vitest `setupFiles`) gives the tests a French browser; tests that switch language put French back (`setLang('fr', false)`).
- TypeScript infers a type predicate from `READY_LANGS.filter((l) => l !== 'fr' && l !== 'en')`, which is `never[]` while only those two are ready: annotate the callback `(l): boolean`.
- `@tamalou/shared` from `apps/web/build/` and `scripts/` runs under Node's type stripping: the symlink resolves outside `node_modules`, so it works; keep imports there erasable (`import type`).
