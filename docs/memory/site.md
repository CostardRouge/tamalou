# The site around the game: home page, pages, addresses

Read before touching `apps/web/index.html`, `en/`, `play/`, `jouer/`, `mentions-legales/`, `build/site.ts`, `build/pages.ts`, `build/analytics.ts`, `src/landing/`, `src/legal/`, `src/audience.ts`, or anything about addresses, SEO, measurement or the service worker's scope. The decisions are ADR-0017 (pages) and ADR-0018 (legal notice, measurement).

## Shape (2026-10-17)

- `build/site.ts` lists the pages (file, address, language, kind, twin) and the site's facts; `build/pages.ts` fills each shell's `<!-- page:head -->` / `<!-- page:body -->` in a `transformIndexHtml` hook with `order: 'post'`, so Vite never rewrites what it writes (relative icon paths per folder, the inline redirect script, JSON). A new page = a shell, a row in `PAGES`, its texts; `test/pages.test.ts` checks shells, relative links, hreflang, words in the HTML.
- `src/landing/text.ts` is the home page's dictionary (French source, English typed against it), read by `markup.ts` at build time and by the scripts in the browser. Everything is plain text with the `\u00a0` escape for no-break spaces (never an HTML entity: React would print it); `<em>` only in `heroTitle`. `cardWords()` names a card in a sentence ("un Roi rouge", "an 8").
- **The first round** (2026-10-17, the owner's pick, direction B): `tutorial.ts` is a pure reducer over a fixed deck (`step(state, action) → { state, after }`, `after` = a timed step the page plays after a pause); `tutorial.tsx` draws it — coach, checklist of the seven moves, a 520×560 table zoomed down on phones — with `CardView` cards that are real buttons when touchable. The deck is chosen so a sensible player meets every move and wins; `test/landing.test.ts` plays it through, and a quick discard is offered only when Malo throws a rank you *know* you hold. A wrong quick-discard tap is forgiven, and the coach says the real rule.
- **The first round's table (2026-10-22, the owner's pick on a canvas, https://claude.ai/artifact/KvuHFtTML3gzXeQypP6Udx)**: 520×480, both hands on one curve halfway between the game's soft arc and its fan (`arcHand()` in `tutorial.tsx`: pivot 5.25 card widths below the foot, neighbours 0.9 widths apart, the canvas's "courbure 0,5"), Malo's turned round as seen from across the table (his first card on my right, so his cards' labels read `where` mirrored), the deck and the discard side by side in the middle, a drawn card beside the discard. Its words follow the line, not a grid: "tes deux cartes de droite" for the peek, "de gauche" for the unknown ones, `where` from "tout à gauche" to "tout à droite". It is fixed, not the player's hand setting: the page must look the same for every visitor.
- **The hand quiz** (`quiz.tsx`, taken from direction C at the owner's request, placed right after the round): five fixed hands, three totals each, values from `pointsOf`, which the test checks against the engine's.
- `main.tsx` mounts the round into `#manche` (replacing the static first step written by `markup.ts`) and the quiz into `#quiz`.
- Language: the home page sets the game's language in memory only (`setLang(lang, false)`) for the card letters; a click on Play or on the language link remembers it (`tamalou-lang`), as Versus does.

## Traps (2026-10-17)

- **Vite 8 is Rolldown**: multi-page inputs go in `build.rolldownOptions.input`; entry names come from the page's folder (`home`, `en`, `play`), shared chunks are named after a module (`CardView-*`, and `remember-*` which carries `src/audience.ts` today). Check after a build that no chunk is named `analytics`/`audience`/`tracker` (Versus's trap: filter lists block the chunk and every page with it).
- The service worker is `/sw.js`, registered from `play/` with `'../sw.js', { scope: '../' }`; every page of `PAGES` is stored under its folder's address (`./en/`, never `en/index.html`: Cloudflare redirects the file to the folder, and a navigation cannot be served a redirected response). A new page = a row in `PAGES` and it is stored and served offline on its own (`web.md`, ADR-0020).
- **The game is at `play/`** (owner, 2026-10-17: one word for both languages, like Versus's `/app/`; it shipped first as `jouer/`). `jouer/` stays as a `moved` page (`build/site.ts`) that forwards with search and fragment, so room and rules links and installs from that time follow; links at the root are forwarded by the home pages' inline script, as is an app installed when the game was at the root (`display-mode: standalone`) — but only when it was just launched (`document.referrer` empty): the game's home screen links back to the site's page («Découvrir le jeu et ses règles», owner's ask 2026-10-20), and that link must land in the installed window too. Room and rules links are built from `location.pathname`, so new ones say `play/`.
- Verified 2026-10-17 with Playwright on `vite preview`: `/`, `/en/`, the game at 390×844 and 1280×900, light and dark, no console error, no horizontal scroll.

## Legal notice and measurement (2026-10-17)

- Ported from Versus (`src/audience.ts`, `build/analytics.ts`, the switch, the tests), not rewritten; Versus's `docs/analytics.md` holds the reasoning (why settings in the head, async, no preconnect, the bounded queue). Read it before changing how the tracker loads.
- **The legal notice states facts the code must keep true** (`src/legal/text.ts`): what is stored on the device (`tamalou-lang`, `tamalou-settings`, the last setup, `tamalou-rooms` tokens for a day), a room's life (memory only, 2 h idle), the per-IP room limit, the events. `test/pages.test.ts` fails when the code sends an event the list does not know; change an event, a stored key or a room's lifetime and update the notice in the same commit.
- Views: the static pages, `/play/` (game home), `/play/game`, `/play/room` (one per screen, from `App`'s effect; `/jouer/…` paths in Umami are from before the move). `game-started` is sent from the home screen, before the `/play/game` view: it carries mode, bots, level, preset and `custom` (rules changed), never names.
- The website id (2026-10-17, given by the owner) is in `build/site.ts`, like Versus's: not a secret, it is in every page. `VITE_UMAMI_WEBSITE_ID` overrides it, empty turns measurement off. A LAN server's host is not in `data-domains`, so the Docker image never reports. Contact address `pommier.steeve+tamalou@gmail.com`, confirmed by the owner (2026-10-17).
- **Trap (2026-10-17)**: a local build with a test id and `VITE_UMAMI_DOMAINS=localhost` loads the real tracker and posts to the real instance (it answered 400 for the fake id). For an end-to-end check, intercept `insight.steevepommier.com` in Playwright (`context.route`) on every page, as Versus's check did, never only some of them. Verified that way 2026-10-17: home → Play → a solo game → an old `/#room=` link (forwarded to the game) → legal notice → switch off gave exactly the expected views and one `game-started`, and no tracker request afterwards.

## The social card (2026-10-19)

- COMMON-PROJECT-SPEC C17: a link shared anywhere unfurls a 1200×630 card in the page's language (`public/og.png`, `og-en.png`), never the icon, named with its size and alt by every page that has a canonical address (`build/pages.ts`); the game and `jouer/` carry none. `OG_IMAGES`, `CARD_COPY` (three lines, a sentence, the button and its note, in the home page's own words) and `COLORS` — the light tokens for what is drawn outside CSS, held to `tokens.css` by `test/icons.test.ts`, which also reads the cards' headers — live in `build/site.ts`. The service worker leaves the cards out (`NOT_OFFLINE` in `build/pwa.ts`). A redrawn card takes a new file name: unfurlers cache by URL.
- Drawn by `scripts/card.mjs` with sharp (the recipe for the throwaway install is in the script, `design.md`): the icon's two cards as an SVG with an `feDropShadow` (librsvg draws it), the words set by pango from the very WOFF2 files `@fontsource-variable` ships for the site, unpacked by wawoff2 because sharp's libvips has pango and freetype but no brotli. **Traps**: fontconfig names those fontsource builds after their default instance — "Bricolage Grotesque 96pt ExtraBold", "Figtree Light", read with `fc-scan` on the unpacked TTF — so the markup sets `font_family` to that string and asks the weight as a number; the font-description parser would read "Light" as a weight, look for a family "Figtree" and fall back to the system's sans in silence, so look at the PNG after any change. sharp refuses `width: 0` (leave it out for a block that must not wrap); the latin subsets have no arrow (drawn as a path). The output is deterministic: a rerun is byte-identical.

## Findability: robots.txt, the sitemap, llms.txt (2026-10-19)

- COMMON-PROJECT-SPEC C17: `build/seo.ts` writes the three files at the site's root at build time (Vite's `generateBundle` and `emitFile`, before `build/pwa.ts` walks the output) and answers them on the dev server, from `build/site.ts` and the dictionaries; the indexed pages link them (`rel="sitemap"`, `rel="alternate" type="text/markdown"`); `test/seo.test.ts` holds them to the pages' heads. **The sitemap lists only the four pages with a canonical address**: the game (`play/`) and `jouer/` say `noindex`, and Search Console flags a noindex address submitted in a sitemap, so the game is reached through the home pages and llms.txt, which links it. Every crawler is allowed, AI crawlers included (the owner's policy, as on steevepommier.com and Versus); `/api/` (the rooms) is disallowed. `lastmod` is the last commit's date, today outside a checkout (the Docker build has no `.git`). The service worker leaves the three files out (`NOT_OFFLINE` in `build/pwa.ts`). Crawlers read `robots.txt` at a host's root only: the GitHub Pages copy's (under `/tamalou/`) is never read, and the Pages build, with no `VITE_SITE_URL`, writes the canonical domain's addresses as its canonical tags do.
- Not done, deliberately: JSON-LD (C17's "where the content has a type"); a `WebApplication` graph like Versus's `build/seo.ts` is the next step if the owner wants it.

## Security headers (2026-10-19)

- COMMON-PROJECT-SPEC C16: one list in `build/security.ts` (HSTS, nosniff, `X-Frame-Options: DENY`, Referrer-Policy, Permissions-Policy, a **Report-Only** CSP), written into `_headers` at the root of the build by `build/seo.ts` — Cloudflare's asset server reads that file for the Worker's pages — and read back at startup by the LAN server (`apps/server/src/headers.ts`, the `/*` block only, applied to every answer, the file itself never served). GitHub Pages sets no header, so the copy there has none; a `<meta>` policy was rejected because a meta CSP cannot carry `frame-ancestors` and would apply to the GitHub Pages copy too. `test/security.test.ts` holds the policy to every inline script of every page (named by **hash**, never `'unsafe-inline'`; `inlineScripts()` in `build/pages.ts` is the list) and the file to the list; the server's test holds its reader to the file's shape. **One `_headers`, one writer (2026-10-20)**: the PWA plugin (`build/pwa.ts`) used to emit its own `_headers` (worker and manifest checked on every load); two assets of one name, so the cache blocks for `/sw.js` and `/manifest.webmanifest` now live in `headersFile()` here and `pwa.ts` writes no headers. **How to apply**: a new inline script goes through `inlineScripts()` or the test fails; styles keep `'unsafe-inline'` because Motion and React write style attributes; `'self'` covers the room's WebSocket on the same host (CSP 3), the service worker and the manifest.
- **Enforce it** by renaming the header in `build/security.ts` (and its test), nothing else, once a tour of the deployed site shows a clean console. Verified 2026-10-19 on the LAN server's build with headless Chromium: the home pages, `jouer/`, both legal notices, the game and a room — zero reports. **Trap**: Zod 4 compiles object parsers with `new Function` and probes for it, which a policy without `'unsafe-eval'` reports on every schema (twenty lines on the room screen); `packages/shared/src/jitless.ts` sets `z.config({ jitless: true })` and is imported **first** by the package's index, because Zod decides at a schema's definition, not at parse time — a config set after the schema modules load changes nothing (measured).
